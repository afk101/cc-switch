# 02 — 覆盖 Profile 运行时启动前的恢复阶段

**What to build:** 当 Codex Profile 启动恢复在建立监听器之前失败时，用户和维护者可以从同一套诊断中准确区分 Profile 校验、待处理生命周期状态恢复、路由读取、本地监听凭证、恢复计划或 Profile 派生状态对账问题，并据此定位下一次开机复现的实际失败点。

**Blocked by:** 01 — 打通 Profile 运行时启动失败的分阶段脱敏诊断

**Status:** resolved

- [x] 为读取并校验 Profile 附加稳定阶段；失败时记录对应分类和安全摘要。
- [x] 为恢复待处理生命周期状态附加稳定阶段；无效或未收敛记录不得误报为运行时启动失败。
- [x] 为读取 Profile 路由附加稳定阶段；路由不存在或路由关闭仍作为正常跳过，不记录失败。
- [x] 为确保本地监听凭证附加稳定阶段；凭证文件 I/O 失败可以识别，但凭证内容不得进入任何诊断输出。
- [x] 为构造恢复计划附加稳定阶段；缺失 Profile 主供应商引用、无效有效设置等问题归入安全且稳定的分类。
- [x] 为开启态 Profile 派生状态对账附加稳定阶段；Home 文件 I/O 失败保留规范路径和操作系统错误类别，但不记录文件正文。
- [x] 每个阶段都复用 01 建立的同一诊断记录、脱敏、日志输出和 `last_error` 持久化链路，不建立第二套格式。
- [x] 任一启动前阶段失败后不继续创建或启动该 Profile 运行时，其他 Profile 仍可继续恢复。
- [x] 高层启动恢复测试分别覆盖待处理状态、监听凭证、恢复计划和 Profile 派生状态对账的代表性失败。
- [x] 测试使用内存数据库、临时 Profile Home 及可控替身，不访问真实 CODEX_HOME、真实监听凭证或真实端口。
- [x] 脱敏负向测试在原始错误中注入模拟 token、API Key 和配置正文，验证应用日志与 `last_error` 均不包含这些内容。
- [x] 所有新增阶段只增强诊断，不修改启动顺序、Profile 派生状态规则、失败隔离或路由启用状态。

## Answer

已为 Profile 校验、待处理状态恢复、路由读取、本地凭证、计划构建和 Home 对账附加稳定阶段，并全部复用统一诊断链路。测试覆盖恢复记录、凭证敏感矩阵、缺失供应商计划和外部 Home 编辑，确认失败 Profile 无后续启动副作用且不影响健康 Profile。
