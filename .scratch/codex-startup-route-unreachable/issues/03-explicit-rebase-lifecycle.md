# 03 — 显式路由操作重建最新基线

Status: resolved

**构建内容：** 用户主动启用、切换供应商或关闭路由时，以操作意图正确处理最新Home：显式新接管建立新backup，关闭恢复最近基线，外部接管后的关闭不回写陈旧配置。

**受阻于：** 02 — 启动恢复安全收敛外部接管。

## 覆盖范围

- `REQ-02`、`REQ-10`、`REQ-11`、`REQ-12`、`REQ-17`
- `SCN-11`、`SCN-12`、`SCN-13`、`SCN-14`、`SCN-20`、`SCN-21`

## Acceptance Criteria

- [x] 显式重新启用以操作当刻Home建立新backup并清除外部接管状态。
- [x] 已启用期间显式切换供应商时，以当前Home替换旧基线并继续完成切换。
- [x] 后续关闭只恢复最近基线的严格路由字段，保留关闭瞬间最新非路由字段。
- [x] 已外部接管后显式关闭不恢复陈旧backup，只清理路由状态。
- [x] 非显式供应商切换流程绝不修改model；显式切换允许应用目标供应商model。
- [x] 任一步骤失败时既有补偿恢复本次操作前状态，不退回更早基线。

## 验证方式

- 运行启用→外部编辑→显式切换→关闭的端到端manager测试。
- 运行缺失Home基线的启用→关闭测试。
- 运行持久化、Home写入、runtime切换失败注入测试。

## 执行约束

- 修改生产代码或测试前调用 `$tdd`。
- 新backup必须在Home接管写入前进入可恢复生命周期。
- `model`授权严格绑定用户显式切换到另一供应商的动作。
- 保留Profile故障转移引用和在途请求既有语义。

## 范围之外

- 不增加运行期配置监控。
- 不更改共享供应商保存对其他Profile的事务语义。

## Comments

- 显式启用不再把供应商默认模型传入路由计划；重新启用同一供应商只接管严格路由字段并保留用户模型。
- 已启用 Profile 显式切换时，在改写 Home 前持久化操作当刻的新版 backup；只有供应商 ID 真正变化时才允许应用目标供应商模型。
- 切换失败补偿同时恢复本次 route plan、运行时、路由、故障转移与模型目录；测试逐字节验证不会退回更早 Home 基线。
- 外部接管后的显式关闭跳过旧 backup 恢复，保持 Home 原样、清理 stale backup，并保留 `External` 所有权状态。
- 验证：route manager 79/79，Codex Profile 144/144，`cargo fmt --all -- --check` 通过。
