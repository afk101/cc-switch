# 02 — 统一恢复与补偿路径，并移除排空契约

**What to build:** 所有 Codex Profile 运行时停止场景统一采用“立即停接”语义。未完成关闭恢复、启用失败补偿和启动恢复都立即拒绝新请求并停止监听器，不再通过任何隐藏路径等待在途路由请求；完成迁移后移除已经失去用途的排空契约和状态。

**Blocked by:** 01 — 显式关闭 Profile 路由时立即停接

**Status:** resolved

- [x] 未完成关闭的恢复流程不等待在途路由请求，并继续保持“先恢复配置、再停止监听器、最后提交关闭状态”的安全顺序。
- [x] 启用残留恢复和启用失败补偿在停止已创建运行时时立即停接，不重新引入 15 秒等待。
- [x] 删除 Profile 前触发的关闭与用户显式关闭使用同一套即时停接语义。
- [x] Profile 运行时生命周期契约不再暴露等待排空能力，仅保留准确表达“拒绝新请求”和“停止监听器”的职责。
- [x] 代理请求边界继续可靠拒绝关闭开始后的新请求，不因移除在途计数而产生可继续进入转发链路的竞态窗口。
- [x] 仅供排空等待使用的 15 秒常量、在途计数、通知状态和辅助逻辑全部移除；仍有其他独立用途的状态必须被明确证明且不得进入关闭等待链路。
- [x] 已经进入转发流程的请求可以在路由关闭甚至重新开启后自行完成，并保持旧供应商快照与用量记录语义。
- [x] 原有排空等待、通知竞争和排空超时测试被替换为即时停接与关闭后拒绝新请求的行为测试。
- [x] 监听器停止超时、配置恢复失败、停止失败及可重试恢复测试继续通过。
- [x] 活跃代码注释和日志统一使用项目领域词汇；历史 findings 与既有设计记录不被改写或删除。
- [x] 相关 Rust 测试套件完整通过，且回归测试不会真实等待 15 秒。

## Answer

所有 Profile 运行时停止入口已统一通过“拒绝新请求并停止监听器”契约执行。运行时与代理层不再暴露或保存排空等待所需的超时、计数和通知状态；显式关闭、删除前关闭、启动恢复、未完成关闭恢复和启用失败补偿均使用同一语义。Rust 全量单测通过 2268 条，2 条忽略，0 条失败。
