# 01 — 显式关闭 Profile 路由时立即停接

**What to build:** 用户显式关闭 Codex Profile 路由后，系统先安全恢复该 Profile 的配置，再立即停止接收新请求并关闭监听器。关闭过程不等待也不主动取消在途路由请求，同时继续保留配置恢复、监听器停止确认和失败重试的安全边界。

**Blocked by:** None — can start immediately

**Status:** resolved

- [x] 当存在不会自行结束的在途路由请求时，用户显式关闭仍能在短且确定的时限内完成，不触发 15 秒等待。
- [x] 关闭先恢复 Profile 的受管理路由字段，再停止接收新请求和关闭监听器；非路由配置及认证文件保持不变。
- [x] 关闭开始后新请求被拒绝，已经进入转发过程的请求不被主动取消，并继续使用关闭前的供应商快照。
- [x] 监听器停止确认继续保留；正常停止近乎立即完成，异常停止仍遵循现有最多 5 秒的保护和错误返回。
- [x] Profile 配置恢复失败时监听器不会停止，路由不会被错误持久化为关闭，并保留可重试恢复状态。
- [x] 监听器停止失败时路由不会被错误持久化为关闭，运行时与恢复记录继续可供后续重试。
- [x] Route Manager 高层回归测试覆盖完整关闭事务及关键事件顺序，不依赖真实网络、真实端口或人工操作。
- [x] 现有前端交互、命令参数和数据库结构保持兼容。
- [x] 用户可见日志使用“停止接收新请求”或“开始关闭”，不再将显式关闭描述为排空等待。

## Answer

显式关闭现在保持“先安全恢复 Profile Home、再拒绝新请求并停止监听器、最后持久化关闭”的事务顺序，不再等待在途请求。高层回归覆盖了短时限完成、配置与认证文件保持、生命周期顺序、在途请求不被主动取消、停止失败可重试及关闭后新请求被拒绝。
