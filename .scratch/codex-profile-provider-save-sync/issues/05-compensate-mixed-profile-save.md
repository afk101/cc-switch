# 05 — 保证混合 Profile 保存整体补偿

**What to build:** 当一个共享供应商同时被关闭态主引用、开启态主引用和故障转移引用使用时，交互式保存采用全引用成功或整体补偿；任一必要同步失败都不会留下数据库、Profile Home、模型目录或运行时版本分裂。

**Blocked by:** 04 — 同步故障转移供应商引用

**Status:** resolved

- [ ] 保存前完成所有可失败的引用读取、状态校验、有效配置构造和文件计划准备。
- [ ] 多个受影响 Profile 在同一次保存中按各自状态执行正确的派生状态更新。
- [ ] 任一 Profile Home 不可写或路径不可用时，整次保存失败并恢复已发生的其他 Home 与模型目录变更。
- [ ] 数据库提交失败时，所有已应用文件和可恢复运行时快照回到保存前可观察状态。
- [ ] 交互式保存不接受或静默报告部分成功。
- [ ] 每个 Profile 内部的运行时快照原子替换；多个 Profile 不要求在同一个瞬间切换。
- [ ] 保存接口返回成功前，所有相关 Profile 的派生状态都已收敛到新供应商版本。
- [ ] 失败错误包含具体 Profile 名称和 Home 路径，能够指导用户修复不可写或状态异常的 Profile。
- [ ] 错误和日志不包含配置正文、API Key、监听器令牌或其他凭证。
- [ ] 混合状态行为测试覆盖 Home 写入失败、数据库失败和运行时状态异常，并断言无残留新版本。

## Answer

保存会先准备全部文件计划、验证所有启用态运行时，再按稳定顺序应用 Home；数据库提交成功后才替换运行时快照。Home 中途失败会反向恢复已写 Profile，数据库提交失败会恢复供应商快照和全部 Home，运行时保持旧版本。混合状态测试覆盖文件失败、数据库失败与运行时缺失，错误只包含 Profile、Home 和脱敏阶段信息。
