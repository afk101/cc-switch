# 03 — 无中断热更新开启态主引用

**What to build:** 当运行中的 Codex Profile 主引用共享供应商时，保存供应商会无中断替换该 Profile 的运行时供应商快照并刷新模型目录，同时保留本地路由接管配置和监听器。

**Blocked by:** 02 — 保存后立即更新关闭态主引用

**Status:** resolved

- [ ] 路由开启的主引用 Profile 保存后，新请求使用更新后的供应商 Base URL 和配置。
- [ ] Profile Home 继续指向本地路由，不被改写为供应商直连 Base URL。
- [ ] 主供应商模型目录更新为新版本，并继续由主供应商决定。
- [ ] 保存过程不重启监听器、不暂停新请求，也不改变 Profile 监听端口。
- [ ] 在途路由请求继续使用进入时取得的旧供应商快照，不被取消、迁移或自动重试。
- [ ] 保存完成后的新请求使用新供应商快照，单个请求不会观察到半旧半新的配置。
- [ ] 路由记录为开启但运行时不存在时，保存明确失败，不把该 Profile 当作关闭态处理。
- [ ] 运行时缺失失败不会改变数据库、Profile Home、模型目录或其他 Profile 的可观察状态。
- [ ] 高层行为测试使用可观察运行时替身验证快照替换、监听器未重启及新旧请求边界。

## Answer

开启态主引用 Profile 现在会在共享供应商数据库提交成功后原子替换运行时供应商快照，同时只刷新主供应商模型目录并保留本地路由接管配置、端口和监听器。行为测试证明在途旧快照不变、新请求取得新 Base URL，且启用记录缺少运行时时会在任何副作用前明确失败。
