# 02 — 保存后立即更新关闭态主引用

**What to build:** 用户保存共享供应商后，所有路由关闭且具有 Profile 主供应商引用的 Profile 立即重建完整 Profile 直连配置和模型目录，无需切换到其他供应商再切回，同时保持 Profile 私有身份状态不变。

**Blocked by:** 01 — 收口共享供应商保存高层接口

**Status:** resolved

- [ ] 路由关闭的主引用 Profile 在一次保存后立即使用新的 Base URL，旧 Base URL 不再出现在受管理直连配置中。
- [ ] 多个路由关闭的主引用 Profile 都同步到同一共享供应商版本。
- [ ] 未引用该供应商的 Profile Home 保持字节不变。
- [ ] Profile 直连配置由更新后的有效供应商设置重建，并继续遵循通用配置、统一会话及其他应用管理内容的现有组合规则。
- [ ] Home 中未写回共享供应商或通用配置的来源不明手工修改不承诺保留，不形成新旧供应商字段混合配置。
- [ ] 主供应商模型目录与完整直连配置在同一次保存中保持一致。
- [ ] `auth.json`、会话历史及其他 Profile 私有身份状态在保存前后保持字节不变。
- [ ] 单个关闭态 Profile 配置无法准备或写入时，保存返回失败且数据库不保留新的供应商版本。
- [ ] 主要回归测试从高层保存接口复现原始 Base URL 缺陷，不访问真实 CODEX_HOME。

## Answer

共享供应商保存现在会为所有关闭态主引用 Profile 重建有效直连配置与主供应商模型目录。高层行为测试覆盖了多个引用 Home、通用配置组合、无关 Home 隔离、Profile 私有身份文件字节不变，以及任一 Home 写入失败时恢复已写 Home 并保留数据库旧版本。
