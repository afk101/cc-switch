# 04 — 同步故障转移供应商引用

**What to build:** 保存仅作为故障转移目标使用的共享供应商时，所有运行中 Profile 的运行时供应商集合立即采用新配置，而关闭态 Profile Home 和主供应商模型目录保持不变。

**Blocked by:** 03 — 无中断热更新开启态主引用

**Status:** resolved

- [ ] 高层保存接口同时识别 Profile 主供应商引用和 Profile 故障转移供应商引用。
- [ ] 路由开启且包含该故障转移供应商的 Profile 重建完整运行时供应商集合。
- [ ] 后续故障转移请求使用保存后的新供应商配置，不需要重启路由或重新选择故障转移列表。
- [ ] 仅作为故障转移引用时，Profile Home 的直连配置保持不变。
- [ ] 仅作为故障转移引用时，主供应商模型目录保持不变。
- [ ] 路由关闭且仅存在故障转移引用时，不写入该 Profile Home。
- [ ] 在途路由请求继续使用旧运行时快照，保存后的新请求使用包含新故障转移配置的快照。
- [ ] 未引用该供应商的运行时供应商集合保持不变。
- [ ] 行为测试同时覆盖开启态故障转移引用、关闭态故障转移引用和无关 Profile。

## Answer

共享供应商保存现在同时发现主引用和故障转移引用。仅故障转移引用的开启态 Profile 会重建并热替换完整运行时供应商集合；关闭态 Profile Home、主供应商模型目录以及无关运行时保持字节或快照不变，行为测试覆盖了三类 Profile。
