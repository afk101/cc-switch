# 06 — 串行化保存与 Profile 生命周期操作

**What to build:** 共享供应商保存与供应商切换、Profile 路由启停和恢复操作并发发生时，系统按稳定顺序串行处理，并让后执行者依据最新引用与路由状态完成操作。

**Blocked by:** 05 — 保证混合 Profile 保存整体补偿

**Status:** resolved

- [ ] 涉及多个 Profile 的保存按稳定 Profile 顺序取得操作锁，不因引用返回顺序变化而改变加锁顺序。
- [ ] 保存、供应商切换、路由启停和恢复使用兼容的锁顺序，不产生循环等待。
- [ ] 操作取得锁后重新读取 Profile 主供应商引用、故障转移供应商引用和路由状态。
- [ ] 保存先执行时，随后切换能够读取已保存的新供应商并完成切换。
- [ ] 切换先执行时，随后保存只更新切换后仍引用该供应商的 Profile。
- [ ] 路由状态在排队期间改变时，保存依据最新状态选择直连配置更新或运行时快照更新，不使用过期分支。
- [ ] 多 Profile 并发场景在确定时限内完成，不发生死锁或永久等待。
- [ ] 并发测试使用受控屏障制造稳定交错，并只断言最终可观察行为和操作顺序语义。
- [ ] 前端不需要实现点击时间排序或“最后点击必胜”的额外协议。

## Answer

共享供应商保存与启用、关闭、切换共用“目录顺序锁 → 稳定排序的 Profile 锁”顺序，并在持锁后重新读取主引用、故障转移引用和路由状态。两个事件驱动并发测试分别固定保存先行与切换先行，证明后执行者依据最新状态收敛且在确定超时内完成。
