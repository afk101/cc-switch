# 07 — 启动时对账完整 Profile 派生状态

**What to build:** 应用异常退出导致部分 Profile 已写入新配置、部分仍保留旧配置时，启动对账以数据库中的共享供应商和 Profile 引用为权威，幂等重建完整 Profile 派生状态并隔离单个失败。

**Blocked by:** 05 — 保证混合 Profile 保存整体补偿

**Status:** resolved

- [ ] 路由关闭的主引用 Profile 在启动对账时重建完整 Profile 直连配置和模型目录。
- [ ] 路由开启的 Profile 在启动恢复时使用数据库权威版本恢复本地路由配置、运行时供应商集合和主供应商模型目录。
- [ ] 故障转移供应商引用在启动恢复后进入正确的运行时供应商集合，但不改变关闭态直连配置或主供应商模型目录。
- [ ] 对账可以重复执行并产生相同结果，不依赖上一次执行停留的具体阶段。
- [ ] 崩溃发生在首个 Home 写入后、多个 Home 写入后或数据库提交后时，重启都能收敛到数据库权威版本。
- [ ] 单个 Profile Home 持续不可写时，该 Profile 记录可诊断错误，其他 Profile 继续对账，应用启动不被整体阻止。
- [ ] 对账错误不包含配置正文、API Key、监听器令牌或其他凭证。
- [ ] `auth.json`、会话历史及其他 Profile 私有身份状态在启动对账前后保持不变。
- [ ] 不新增跨文件系统事务日志、全局请求屏障或持久化 schema。
- [ ] 启动对账测试使用临时 Home 和内存数据库覆盖崩溃残留、重复执行及失败隔离场景。

## Answer

启动流程现在先以数据库权威版本逐个对账完整 Profile 派生状态：关闭态重建有效直连配置和模型目录，开启态刷新主目录后使用有效主供应商与故障转移集合恢复本地路由和运行时。对账可重复执行；单个不可写 Home 只记录包含 Profile/Home 的脱敏错误，不阻断其他 Profile，也不触碰私有身份文件或新增 schema。
