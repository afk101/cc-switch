# 导出诊断日志 ZIP

## 问题陈述

CC Switch 会在应用配置目录的 `logs` 子目录持续写入运行日志、轮转日志和按需开启的请求正文日志，但当前界面只能控制日志开关与级别。用户排障时必须自行定位可能被自定义过的应用配置目录、手工压缩整棵日志目录，再自行寻找输出文件，流程繁琐且容易漏掉嵌套目录。

## 目标

- 用户可以从应用诊断日志设置面板一键把整个日志目录树导出为 ZIP。
- 导出不暂停代理服务或日志写入，不阻塞界面主线程。
- 输出默认出现在系统下载目录；下载目录不可用时出现在系统桌面目录。
- 大目录导出保持有界内存占用，并在失败时不留下看似成功的半成品。
- Windows、macOS、Linux 上保持一致的可观察行为。

## 非目标

- 不对导出内容做额外脱敏，也不承诺导出包适合公开分享。
- 不包含 `logs` 目录之外的 `crash.log*`、数据库、配置或环境信息。
- 不提供保存位置选择、压缩进度、取消导出、自动打开目录或“打开所在文件夹”操作。
- 不暂停日志、代理或路由服务来生成严格一致的文件系统快照。
- 不改变现有日志生成、轮转或清理策略。

## 解决方案

在“设置 → 高级设置 → 应用诊断日志”面板增加“导出日志”按钮。点击后，应用在后台读取当前生效应用配置目录下的整个 `logs` 树，将普通文件以原相对路径写入包含 `logs/` 顶层目录的 ZIP。ZIP 使用时间戳命名，优先保存到系统下载目录，无法使用下载目录时回退桌面。导出期间按钮显示忙碌并禁止重复点击；成功后展示完整保存路径。

## 用户故事

1. 作为遇到问题的 CC Switch 用户，我想从日志设置处一键导出日志，从而无需手工寻找应用配置目录。
2. 作为使用自定义应用配置目录的用户，我想导出当前实际生效目录中的日志，从而不会误导出默认目录中的旧数据。
3. 作为需要排查请求协议问题的用户，我想让导出包包含嵌套的 `proxy-bodies`，从而保留完整诊断证据。
4. 作为普通桌面用户，我想让导出包自动出现在下载目录，从而不必选择保存位置。
5. 作为下载目录不可用的用户，我想让导出包回退到桌面，从而仍能完成导出。
6. 作为保留历史日志包的用户，我想让新导出避免覆盖同名文件，从而不会丢失旧证据。
7. 作为代理仍在运行的用户，我想在导出时继续使用 CC Switch，从而不因收集日志中断工作。
8. 作为拥有大量日志的用户，我想让导出使用有界内存，从而不会因为数 GB 日志导致应用内存暴涨。
9. 作为用户，我想在导出期间看到按钮忙碌且不能重复点击，从而知道操作仍在执行并避免重复任务。
10. 作为用户，我想在成功后看到 ZIP 的完整路径，从而能够准确找到导出文件。
11. 作为没有日志的用户，我想收到明确提示且不生成空包，从而不会误以为空包包含诊断信息。
12. 作为注重隐私的用户，我想让导出严格停留在真实日志目录树中，从而不会通过符号链接意外打包目录外文件。
13. 作为磁盘空间不足或目录不可写的用户，我想收到失败提示且不留下半成品，从而不会把损坏 ZIP 当作成功结果。
14. 作为 Windows、macOS 或 Linux 用户，我想获得一致的导出行为，从而无需了解平台路径差异。

## 可观察 Requirements

- **REQ-01**：应用诊断日志面板必须显示“导出日志”按钮。
- **REQ-02**：点击按钮必须导出当前生效应用配置目录下 `logs` 目录树中的全部普通文件，包括所有嵌套目录中的普通文件。
- **REQ-03**：ZIP 必须保留 `logs/` 顶层目录和源文件的相对目录结构。
- **REQ-04**：导出不得包含 `logs` 目录外的文件，也不得跟随或归档符号链接。
- **REQ-05**：输出文件名必须以本地时间生成 `cc-switch-logs-YYYYMMDD-HHmmss.zip`；若目标已存在，必须自动使用带递增序号的可用名称且不得覆盖旧文件。
- **REQ-06**：应用必须优先把 ZIP 保存到系统下载目录；下载目录无法解析、不是可用目录或无法创建输出时，必须回退系统桌面目录。
- **REQ-07**：若下载目录与桌面目录都不可用，导出必须失败并向用户显示错误。
- **REQ-08**：导出期间按钮必须显示忙碌状态并禁止同一界面重复触发；压缩不得阻塞界面主线程。
- **REQ-09**：导出成功后必须显示成功消息与 ZIP 完整路径，不得自动打开目录。
- **REQ-10**：`logs` 不存在或不包含任何可归档普通文件时，必须提示“暂无可导出的日志”，且不得生成 ZIP。
- **REQ-11**：导出必须采用尽力而为快照；枚举后因写入、缩短、轮转、清理而无法继续读取的源文件允许静默跳过，不得暂停日志或代理服务，也不得在完成提示中报告跳过数量。
- **REQ-12**：目标目录权限、磁盘空间、ZIP 写入、完成或落位失败时，导出必须失败，不得留下最终命名的半成品，也不得破坏已有 ZIP。
- **REQ-13**：导出多 GB 日志时必须流式处理文件内容，内存占用不得随单个文件或全部日志总大小线性增长。
- **REQ-14**：所有新增用户可见文案必须支持项目现有的简体中文、繁体中文、英语和日语本地化。
- **REQ-15**：上述行为必须支持项目声明的 Windows、macOS 和 Linux 桌面平台，并使用平台系统目录解析能力。

## Scenarios

- **SCN-01 — 正常导出**
  - Given 当前日志目录包含顶层日志、轮转日志和嵌套请求正文日志
  - When 用户点击“导出日志”且下载目录可用
  - Then 下载目录出现带时间戳的 ZIP，内部以 `logs/` 为顶层并保留全部普通文件的相对结构，界面显示成功消息和完整路径

- **SCN-02 — 自定义应用配置目录**
  - Given 用户已把应用配置目录切换到自定义位置
  - When 用户导出日志
  - Then ZIP 来源是当前实际生效配置目录的 `logs`，而不是硬编码的默认目录

- **SCN-03 — 下载目录回退桌面**
  - Given 系统下载目录无法解析、不是目录或无法创建输出，且桌面目录可用
  - When 用户导出日志
  - Then ZIP 保存到桌面，界面展示桌面中的完整路径

- **SCN-04 — 两个目标目录均不可用**
  - Given 下载目录和桌面目录都不可用
  - When 用户导出日志
  - Then 用户看到失败提示，任何位置都没有最终命名的半成品

- **SCN-05 — 无日志**
  - Given `logs` 不存在、为空或只包含目录与符号链接
  - When 用户点击“导出日志”
  - Then 用户看到“暂无可导出的日志”，且不生成 ZIP

- **SCN-06 — 同名文件避让**
  - Given 目标目录已有按当前时间戳命名的 ZIP
  - When 用户导出日志
  - Then 新 ZIP 使用递增序号，旧 ZIP 内容保持不变

- **SCN-07 — 导出期间文件追加**
  - Given 某日志在枚举后仍持续追加
  - When 后台导出读取该文件
  - Then 归档读取量受枚举时快照长度约束，导出能够结束且不会无限追随追加内容

- **SCN-08 — 导出期间文件轮转或消失**
  - Given 某日志在枚举后被缩短、轮转、删除或变得不可读取
  - When 后台导出处理该文件
  - Then 该瞬时变化的文件可被静默跳过，其余文件继续导出，成功提示不展示跳过数量

- **SCN-09 — 符号链接边界**
  - Given `logs` 内存在指向目录内或目录外目标的符号链接
  - When 用户导出日志
  - Then ZIP 不包含符号链接本身及其目标内容

- **SCN-10 — 防重复交互**
  - Given 一次导出正在执行
  - When 用户观察或再次尝试点击按钮
  - Then 按钮显示忙碌且不可再次触发导出，其他界面工作不被后台压缩阻塞

- **SCN-11 — ZIP 写入失败**
  - Given 目标目录在归档期间磁盘满、断开或拒绝写入
  - When ZIP 写入、完成或最终落位失败
  - Then 用户看到失败提示，既有同名文件不变，最终命名路径不存在新的半成品

- **SCN-12 — 多语言界面**
  - Given 用户使用任一现有受支持界面语言
  - When 用户查看和使用日志导出功能
  - Then 按钮、忙碌、成功、无日志与失败信息均使用对应语言资源

## 关键决策

- 默认且唯一范围是整个 `logs` 目录树，不排除 `proxy-bodies`，也不额外加入目录外的崩溃日志。
- 点击后不展示敏感内容确认，不弹保存对话框；导出物不标注为“已脱敏”或“可安全分享”。
- 大文件操作只提供按钮忙碌态，不提供进度条或取消协议，以保持本地导出流程简单。
- 运行中变化采用尽力而为语义；静默跳过瞬时失效文件，不向用户展示跳过数量。
- 成功仅展示完整路径，不自动打开目录或附加打开操作。
- 下载目录失败时回退桌面，兼顾固定位置的简单性与多平台可用性。

## 实施决策

- 后端提供一个高层导出接口，负责解析当前应用配置目录、系统下载/桌面目录、归档与最终路径返回；前端不传入任意源路径或目标路径。
- 归档服务以公开的路径输入/结果接口形成可测试 seam；先枚举不跟随链接的普通文件清单及快照长度，再以限长流式复制写入 ZIP。
- ZIP 先写入目标目录内的临时文件，显式完成后再原子落位；同名选择与临时文件生命周期均由后端负责。
- 后端耗时归档在阻塞任务线程执行，命令级与界面级都防止并发重复导出。
- 用户可见错误使用稳定、可本地化的错误类别，而不是依赖平台原始错误文本来决定交互。
- 新增常量进入项目现有常量模块；新增 JavaScript/TypeScript 函数使用 JSDoc，并保持单一职责。

## 错误行为与恢复

- 无日志是可理解的业务结果：不创建输出，前端显示“暂无可导出的日志”。
- 下载目录不可用不是最终失败：自动尝试桌面目录。
- 源文件在快照之后发生瞬时变化时，跳过该文件并继续；不把跳过数量暴露给用户。
- 目标解析、目录权限、磁盘、ZIP writer、finish 或原子落位失败是整体失败：清理临时文件，保留任何既有 ZIP，并允许用户稍后重试。
- 前端无论成功或失败都恢复按钮可用状态；失败通过错误提示呈现，不保留前端伪成功状态。

## 兼容性

- 不修改数据库、现有设置结构或日志格式，不需要 migration。
- 不改变既有日志开关、级别、轮转、清理、代理或路由行为。
- 使用现有 Tauri 2、ZIP 与临时文件依赖，不新增前端文件系统写权限。
- Windows、macOS、Linux 使用 Tauri 系统目录解析；Linux 尊重 XDG 用户目录配置。
- ZIP 条目使用跨平台可移植的正斜杠相对路径，不泄露源绝对路径。

## 测试决策

- 测试只观察公开行为，不断言私有 helper 调用或内部遍历顺序。
- 使用逐条 red → green vertical loops：先建立失败测试，再增加足以通过的实现。
- 复用项目现有 Rust `tempfile` + `ZipArchive` 测试惯例，独立检查实际 ZIP 条目和文件内容。
- 复用设置组件测试中的 Tauri invoke mock 与 toast 交互惯例，检查用户可见状态。
- 最终运行聚焦 Rust 测试、前端组件测试、TypeScript 类型检查、格式检查，以及项目完整测试套件。

## Test Seams

- **归档服务公开接口**：以临时日志根目录和目标目录驱动，观察返回路径与实际 ZIP；覆盖 REQ-02–05、REQ-10–13，SCN-01、SCN-05–09、SCN-11。
- **Tauri 导出命令公开接口**：注入/控制系统目录解析结果并观察导出结果类别；覆盖 REQ-06–07、REQ-15，SCN-02–04。
- **应用诊断日志面板公开交互**：通过渲染组件、点击按钮和 mock 后端响应观察按钮、toast 与路径；覆盖 REQ-01、REQ-08–10、REQ-14，SCN-01、SCN-05、SCN-10、SCN-12。

## 范围之外

- 日志内容预览、筛选、选择性导出与脱敏编辑器。
- 自动上传 GitHub Issue、客服系统或云存储。
- 导出 `crash.log*`、数据库、配置、系统信息或 CLI 会话日志。
- 日志清理、保留周期、总量上限或 `proxy-bodies` 生命周期调整。
- 精确进度、预计剩余时间、取消、暂停与恢复。

## 补充说明

- 当前本机实例的日志目录约 2.70 GB、2160 个文件，其中绝大部分为未脱敏正文的 `proxy-bodies`；这验证了流式归档和后台执行的必要性。
- 由于用户明确选择无风险确认，产品文案必须保持中性，只称“导出日志”，不能暗示内容已经安全处理。
