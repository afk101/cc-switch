# 01 — 打通一键导出日志主路径

**构建内容：** 用户可以从应用诊断日志面板点击按钮，将当前实际日志目录的全部普通文件流式打包到系统下载目录，并在界面看到成功路径；导出期间按钮保持忙碌且无法重复触发。

**受阻于：** 无——可以立即开始。

## 覆盖范围

- REQ-01、REQ-02、REQ-03、REQ-05（标准时间戳路径）、REQ-06（下载目录正常路径）、REQ-08、REQ-09、REQ-13、REQ-14、REQ-15。
- SCN-01、SCN-02、SCN-10、SCN-12。

## Acceptance Criteria

- [x] 应用诊断日志面板在所有现有界面语言下显示可理解的“导出日志”操作。
- [x] 点击后从当前生效应用配置目录读取 `logs`，ZIP 内保留 `logs/` 顶层和嵌套相对结构。
- [x] ZIP 以时间戳命名并保存到系统下载目录，成功提示展示完整路径且不自动打开目录。
- [x] 导出期间按钮显示忙碌并禁止重复点击，后台压缩不阻塞界面主线程。
- [x] 多 GB 文件内容通过流式方式归档，不把单个文件或整棵目录读入内存。
- [x] 新增常量进入项目常量模块；新增 TypeScript 函数具有合规 JSDoc，并保持单一职责。

## 验证方式

- 从归档服务公开 seam 创建含顶层与嵌套普通文件的临时日志树，验证实际 ZIP 名称、条目、内容和目录结构。
- 从设置面板公开交互 seam 验证点击、忙碌防重、成功 toast 和完整路径。
- 运行相关 Rust 单测、前端组件测试、TypeScript 类型检查与格式检查。

## 执行约束

- 修改生产代码或测试前必须调用并遵循 `$tdd`，逐个行为完成 red → green。
- 前端不得向后端传入源目录或任意目标路径；后端解析当前应用配置目录与系统下载目录。
- 不新增保存对话框、进度条、取消交互或自动打开目录。
- 不加入 `logs` 目录之外的文件，不改变现有日志写入与轮转行为。

## 范围之外

- 下载目录失败后的桌面回退。
- 无日志、同名冲突、符号链接、运行中变化和原子失败清理等韧性边界；由后续 issue 覆盖。
