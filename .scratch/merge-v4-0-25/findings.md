## 已确认的兼容决策

1. 保留上游 4.x 主界面，并接回 Codex Home 选择、Profile 管理和独立路由开关。
2. 已存在 Profile 时，Codex 的配置所有权仍归 Profile。上游全局模式的启动恢复跳过 Codex，避免同一 Home 被两套恢复逻辑覆盖。其他应用继续使用上游模式与聚合功能。全局 Codex 聚合没有扩展成每 Profile 聚合。
3. 共享供应商保存继续经 Profile 路由管理器同步全部引用，保留失败补偿和私有身份隔离。
4. 保留上游后台用量写入，同时将 Profile 标识带入后台线程。Profile 请求从自己的路由快照选家。
5. 数据库版本采用上游 v24。旧分支 v19 与上游 v19 含义不同，需要幂等补齐 Mcode 开关和 Profile 结构，不能只改版本号。
6. 保留工具调用空 ID 的顺序回填，同时合并上游孤儿结果处理、上下文压缩和流式终止修复。
7. MCP 投影复用上游 Codex 专属格式转换；保留本分支的日志导出、按 Profile body dump 和周期清理。
8. 保留 Codex 普通图片输入不被静默删除的本地规则，同时接入上游 OpenRouter 明确拒绝图片的 404 重试。普通路由 404 仍不触发改写。
