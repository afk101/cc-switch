### 每日额度接口与认证

- **现状事实：** kwoo-client 前端请求 `GET /api/llm/daily-token`。前端传给其本地服务的 `X-Auth-Access-Token`，不等于最终远端请求头。来源：[useDailyTokenUsage.ts:83](/Users/qihoo/Documents/A_Finer/kwoo-client/src/components/settings/hooks/useDailyTokenUsage.ts:83)。
- **现状事实：** kwoo-client 本地服务向认证服务的同一路径发送 GET 请求，远端请求使用 `Authorization: Bearer <access_token>`。来源：[llm.js:167](/Users/qihoo/Documents/A_Finer/kwoo-client/server/routes/llm.js:167)、[llm.js:763](/Users/qihoo/Documents/A_Finer/kwoo-client/server/routes/llm.js:763)。
- **现状事实：** 每日 Token 余额使用 `data.wis_gpt_used` 与 `data.wis_gpt_total`。它们是 WisGPT 的独立额度，不是其他外网模型额度。现有客户端按 `max(0, total - used)` 计算剩余。来源：[dailyTokenUsage.ts:35](/Users/qihoo/Documents/A_Finer/kwoo-client/src/components/settings/utils/dailyTokenUsage.ts:35)、[dailyTokenUsage.ts:58](/Users/qihoo/Documents/A_Finer/kwoo-client/src/components/settings/utils/dailyTokenUsage.ts:58)。
- **现状事实：** WisCode 将登录信息写入用户数据目录下的 `auth.json`，包含 `access_token` 与 `host`。`host` 由 URL 的 `.host` 提取，可能只有域名和端口，没有 `https://`。不能直接把它当完整 URL 使用。来源：[device-auth.js:39](/Users/qihoo/Documents/A_Finer/kwoo-client/server/routes/device-auth.js:39)、[device-auth.js:118](/Users/qihoo/Documents/A_Finer/kwoo-client/server/routes/device-auth.js:118)。
- **现状事实：** 生产数据目录默认为 `~/.wiscode`。本机该目录存在，`auth.json` 可解析，并且 `host`、`access_token` 为非空字符串。调研阶段仅检查字段，不输出凭据；后续真实接口与原生面板结果见“实施验证”。来源：[user-data-dir.js:29](/Users/qihoo/Documents/A_Finer/kwoo-client/shared/user-data-dir.js:29)及本机配置的脱敏检查。

### 接口已存在两种不同单位

- **现状事实：** 最新 kwoo-client 不再把该接口的所有结果都视为每日 Token。显式 `wis_gpt_quota_mode = TOKEN` 才读取每日 Token；`CREDIT` 读取 WisGPT 每周积分；`NONE` 隐藏额度。模式缺省时，还要兼容旧服务的返回形式。来源：[dailyTokenUsage.ts:94](/Users/qihoo/Documents/A_Finer/kwoo-client/src/components/settings/utils/dailyTokenUsage.ts:94)、[接口契约:1150](/Users/qihoo/Documents/A_Finer/kwoo-client/docs/api-contracts/rest-api.md:1150)。
- **现状事实：** 每周积分与 Token 不是相同单位。积分不能直接换成 `xxM Token`，也不能在服务端明确为积分模式时悄悄改读残留的 Token 字段。本需求已确认只展示每日 Token，不扩展每周积分展示。

## 我补充的技术设计

### 展示与数值含义

- **我的建议｜一行布局：** 左侧为绿色细额度条，中间为百分比，右侧为剩余额度。示意：`［━━━━━━────］ 76% 76M`。沿用面板现有字体、圆角、间距与深浅主题，不添加图标或新卡片。
- **我的建议｜统一表示剩余：** 条的填充和百分比都表示剩余比例，而不是已用比例。这样它们与右侧“剩余多少额度”的含义一致。
- **我的建议｜计算规则：** 对有效每日 Token 数据，`剩余 = max(0, 总额 - 已用)`；`剩余百分比 = 剩余 / 总额 × 100%`，展示范围限制为 0%～100%。例如总额 100,000,000、已用 24,000,000，应显示 76% 和 76M。
- **我的建议｜格式：** `1M = 1,000,000 Token`。右侧始终使用 M，最多一位小数并去掉末尾 `.0`。正数不足 0.1M 时显示 `<0.1M`，避免误显示为用尽。百分比取整数，正数不足 1% 时显示 `<1%`。
- **我的建议｜真实零值：** 剩余为零时显示空条、`0%`、`0M`。不能把零余额当成缺失，也不保留假的最小填充宽度。
- **我的建议｜位置范围：** 放在公共底栏，因此“配置”和“用量”两个页签都可看到。是否开启轻量模式不影响显示；“轻量模式上方”描述位置，不是开启条件。
- **我的建议｜账号范围：** 展示 `~/.wiscode/auth.json` 所代表账号的 WisGPT 额度，不随当前 Claude Code／Codex 供应商或 Codex Profile 切换，不混入现有供应商余额。

### 打开面板后的正常流程

1. **我的建议：** 在现有的面板打开入口触发一次独立的额度查询。同一次弹出的重复通知不重复请求；下一次真正打开仍发新请求，不沿用现有供应商查询的 10 秒防抖。
2. **我的建议：** Rust 后端检查当前用户 Home 下的 `.wiscode` 是否为目录。没有目录则返回不展示，不发额度请求，也不创建目录。
3. **我的建议：** 后端只读 `.wiscode/auth.json`，复用其中的 `host` 与 `access_token`。不读取开发目录 `.wiscode-dev`，不遍历 WisCode 数据库寻找其他账号。
4. **我的建议：** `host` 是纯主机名时补 `https://`，再构造 `/api/llm/daily-token`。已带协议时先验证目标；不向无法确认的目标或明文 HTTP 发送登录凭据。不因跨主机重定向转发认证头。
5. **我的建议：** 使用上述 Bearer 认证直接请求远端接口，不依赖 kwoo-client 进程或其本地 HTTP 服务正在运行。
6. **我的建议：** 校验 HTTP、业务成功状态和数据内容，再按已确认的计费模式规则处理。不能仅凭 HTTP 200 就使用错误响应中的字段。
7. **我的建议：** 前端只接收展示所需数值与可见状态，不接收登录凭据。成功后在原面板中更新这一行，并沿用已有的尺寸重算机制。

### 加载、失败和恢复

- **我的建议｜不阻塞：** 打开面板不等待额度请求完成。轻量模式、打开主窗口、退出和供应商切换始终可用。
- **我的建议｜不展示旧余额：** 每次打开先清除本条上次结果，成功后再显示。加载期间不显示伪造的 0M 或 100%。这样无需为旧数据额外增加文字标识或缓存机制。
- **我的建议｜失败表现：** 目录存在但认证文件缺失、不可读、格式错误，或 host／token 缺失时，隐藏该行，不弹登录框。网络失败、超时、认证过期、业务失败或返回数据不完整时，同样隐藏该行，不影响其余面板。
- **我的建议｜数据校验：** 总额必须是有限正数，已用必须是有限非负数。总额缺失或为零时视为不可展示，不做除零计算。已用超过总额时将剩余钳制为零。
- **我的建议｜恢复方式：** 不做自动重试；下一次打开重新检查目录、读取认证文件并请求。创建目录、恢复网络或重新登录 WisCode 后，无需重启 CC Switch。
- **我的建议｜快速开关与账号变化：** 只采用最新一次弹出、当前身份对应的结果。旧请求晚返回时，不能覆盖新请求或把已移除目录／已切换账号的余额重新显示出来。
- **我的建议｜安全：** 不创建、修改或刷新 `.wiscode` 中的登录信息。不把 token、认证头、完整认证文件或响应正文写入日志和前端；只保留脱敏错误类别。
