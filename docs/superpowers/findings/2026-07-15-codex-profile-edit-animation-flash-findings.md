# Codex Profile 编辑动画黑闪调查

## 用户反馈

- 从 Profile 管理列表第一次打开“编辑 Profile”时，会先黑一下再显示内容。
- 预期是切换过程流畅，不能短暂露出下层遮罩。

## 调查发现

- `CodexProfileManagerDialog` 在 `view.kind` 变化时用 `key` 重新挂载 `.codex-profile-dialog-view`。
- `.codex-profile-dialog-view` 的进入关键帧从 `opacity: 0` 开始。
- Profile 管理和编辑实际是同一个 Dialog 内的两个视图；切换时外层深色遮罩仍然存在。
- 因此新视图重新挂载后的第一帧完全透明，造成用户看到下层遮罩，形成黑闪。
- 外层 Dialog 自身已有独立的打开和关闭动画，不需要内部视图再次从完全透明开始。
- 点击编辑时先更新 `view`，`isEditLoading` 直到随后执行的 `useEffect` 才设为 `true`；这两个状态更新之间会渲染一帧没有正文的编辑弹窗。
- 用户进一步确认可见闪动来自短暂加载页与最终编辑表单高度不同；请求完成很快时，弹窗连续改变两次高度。

## 根本原因

第一次修复移除 `opacity` 后用户确认黑闪仍存在，排除了透明度是唯一原因。

最终确认的主要原因是加载页与编辑表单高度不同。快速请求让用户在很短时间内看到弹窗从列表切到矮加载页、再扩展为完整表单，视觉上表现为闪动。

## 修复方向

- 内部视图不再使用 `transform`，改用不会创建嵌套变换合成层的相对定位位移动画。
- 点击编辑后保持列表界面不变，在后台读取状态；请求完成后一次性切换到最终编辑页，不再渲染中间加载页。
- 使用请求序号忽略弹窗关闭后或较旧请求返回的结果，避免异步结果重新打开过期编辑视图。
- 保留外层 Dialog 的淡入淡出，继续负责真正的弹窗打开和关闭动画。
